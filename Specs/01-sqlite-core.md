# Plan 01: SQLite core

## Goal

Replace the starter app's implicit database assumptions with one tested SQLite engine and typed Swift access layer. This plan does not build the final UI.

## Planning

1. Read `Specs/00-architecture.md`, inspect the Xcode project and current source, then check `git status` and recent commits. Preserve user changes. Use a `codex/` branch if a branch is needed; do not reset or overwrite work.
2. Check the available iOS Simulator destinations with `xcodebuild -showdestinations -scheme 'SQLite Viewer' -project 'SQLite Viewer.xcodeproj'`. Select an available iPhone simulator for tests. If none exists, build for `generic/platform=iOS Simulator` and record the test limitation in the commit body.
3. Download the official SQLite 3.53.4 archive `sqlite-amalgamation-3530400.zip` from the SQLite download page. Verify SHA3-256 `628a44cfe82c66aed1ccbbe85a562d2e33ebe64b3288981ed76285612227934e` before vendoring it. Keep the exact source URL, version, checksum, and compile options in `ThirdParty/SQLite/README.md`.

## Implementation

1. Add the amalgamation's `sqlite3.c` and `sqlite3.h` as a C target or app target source. Expose the header to Swift with a bridging header or Clang module. Define `SQLITE_ENABLE_DBSTAT_VTAB` and `SQLITE_OMIT_LOAD_EXTENSION` for the C compilation. Remove any competing SQLite system linkage.
2. Add `DatabaseSession` as the sole owner of a connection. Its API must open a local URL read/write, close cleanly, and execute a prepared statement with bound values. Finalize statements with `defer` on every path. Preserve SQLite error code, extended code, message, and offending SQL in a structured error.
3. Add typed `SQLiteValue` cases for NULL, `Int64`, `Double`, `String`, and `Data`. Copy text and BLOB bytes before stepping or finalizing again. Add one identifier quoting helper and use it for all generated SQL in later plans.
4. Add a small test fixture builder in the test target. It should create temporary databases with ordinary tables, NULLs, text, BLOBs, indexes, and a `WITHOUT ROWID` table. Keep fixtures generated by code so tests do not depend on an external file.

## Testing

1. Build the app for iOS Simulator with `xcodebuild build -project 'SQLite Viewer.xcodeproj' -scheme 'SQLite Viewer' -destination 'generic/platform=iOS Simulator'`.
2. Run unit tests on the selected simulator with `xcodebuild test -project 'SQLite Viewer.xcodeproj' -scheme 'SQLite Viewer' -destination 'platform=iOS Simulator,id=<selected-id>'`.
3. Assert all five SQLite value types round-trip, identifier quoting handles a name containing `"`, errors expose SQLite codes, and `SELECT * FROM dbstat LIMIT 1` prepares successfully. Confirm compile options at runtime with `sqlite3_compileoption_used` or `PRAGMA compile_options`.

## Review

Review the diff for duplicate SQLite linkage, leaked statement pointers, unfinalized statements, unsafe pointer lifetimes, bundled build artifacts, and changes outside this plan. Run `git diff --check` and inspect `git status`.

## Commit

Stage only this plan's source, project, test, and vendor files. Commit with a short title such as `Add bundled SQLite core` and a body explaining why `dbstat` is compiled in, what the access layer covers, and which build and test commands passed. Do not commit generated Xcode data.

## Done when

The app builds, the SQLite access layer is tested, and `dbstat` is available through the same library that future features will use.
